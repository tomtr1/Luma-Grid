# LumaGrid

**Place. Clear. Glow.** A native iOS block-placement puzzle game (SwiftUI, iOS 17+), free to play, with optional ads and in-app purchases.

> "LumaGrid" is a **working title**. App Store name availability, domain, and trademarks have **not** been checked. Name, tagline, bundle ID, product IDs, and URLs are all centrally configurable (see [Configuration](#configuration)).

## The game

- 9×9 board, tray of three pieces (1–5 cells, no rotation), placed in any order. A new tray is dealt only once all three are used.
- Completing a row or column clears it. Rows and columns cleared by the same move are all scored, and their shared intersection cells are removed once.
- **Combos:** clearing lines on consecutive placements earns a growing bonus.
- **Lumen Pulse (the twist):** some pieces carry a **Prism** tile, shown with a ✦ star as well as its color. When a cleared line contains a Prism, the Lumen meter charges by one (at most once per move). At 3 charges, **Pulse** is ready: tap Pulse, tap an area to preview it, then tap inside the preview to clear every tile in that 3×3 area. Pulse doesn't score points and doesn't charge the meter.
- The round ends when no remaining piece fits anywhere **and** Pulse is not ready. If you're stuck but Pulse is charged, the game prompts you to use it. The board is never altered silently.
- **Daily Puzzle:** the same pieces for everyone on a given calendar date (the seed comes from the date). Finishing it pays a one-time coin bonus per date, and its best score is tracked separately.
- Interrupted rounds are saved after every move and can be continued from Home.

### Scoring (in `ScoreCalculator`, covered by tests)

```
placement = cellsPlaced × 1
lines     = 10 × linesCleared²             (1 line 10, 2 lines 40, 3 lines 90, …)
combo     = 15 × (comboStreak − 1)          only when the move clears ≥ 1 line
```

### Coins (in `RoundRewardCalculator` / `EconomyConfiguration`)

`round coins = min(40, 5 + score / 100)`, plus 25 the first time each date's Daily Puzzle is finished. An optional rewarded ad gives 50 coins. Coins only buy cosmetic themes (Tide 400, Ember 600). Nebula and Sunrise are paid theme packs. All of these values are in `EconomyConfiguration.standard` and `ThemeCatalog`.

Architecture rules:
- The engine (`GameSession`) applies each move as one atomic transition (placement → line detection → clearing → scoring → Lumen → combo → tray → round state) and returns an immutable `PlacementOutcome`. The UI only animates that outcome.
- The engine doesn't know about ads, purchases, or the player. Piece generation is seeded (`SplitMix64`) and identical for every player.
- Ads and StoreKit sit behind protocols and services (`AdCoordinator`, `InterstitialAdProviding`, `RewardedAdProviding`, `PurchaseProcessor`), so their rules are unit-tested with test doubles.

## Requirements

- macOS with **Xcode 16 or later** (the project uses Swift tools 6.0 for the package and String Catalogs). The app target compiles in Swift 5 language mode; the package uses Swift 6 mode.
- iOS **17.0** deployment target. iOS 17 was chosen for the Observation framework (`@Observable`), SwiftUI's `PurchaseAction`, and modern `onChange` and coordinate-space APIs.
- Network access on first build so Xcode can fetch the Google Mobile Ads and UMP Swift packages.

## Build, run, test

**In Xcode:** open `LumaGrid.xcodeproj`, choose the **LumaGrid** scheme and an iPhone simulator, then press ⌘R. The scheme's Run action uses `LumaGrid/Resources/LumaGrid.storekit`, so the shop shows local test products with no App Store Connect setup. Press ⌘U to run the unit and UI tests.

**Command line:**

```sh
# Engine + services tests (macOS or Linux, no Xcode needed)
swift test --package-path Packages/LumaGridCore

# Linux without a local toolchain:
docker run --rm -v "$PWD":/repo -w /repo swift:6.1-noble swift test --package-path Packages/LumaGridCore

# App build + all tests on a simulator (pick a device listed by `xcrun simctl list devices`)
xcodebuild -resolvePackageDependencies -project LumaGrid.xcodeproj -scheme LumaGrid
xcodebuild test -project LumaGrid.xcodeproj -scheme LumaGrid \
  -destination 'platform=iOS Simulator,name=iPhone 16'

# Release configuration build (ads disabled unless real IDs are configured)
xcodebuild build -project LumaGrid.xcodeproj -scheme LumaGrid -configuration Release \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO
```

**Regenerating the Xcode project** (only after editing `project.yml`): install XcodeGen (`brew install xcodegen`) and run `xcodegen generate`.

**Regenerating assets:** `python3 Scripts/generate_icon.py LumaGrid/Resources/Assets.xcassets/AppIcon.appiconset/AppIcon-1024.png` and `python3 Scripts/generate_sounds.py LumaGrid/Resources/Sounds` (needs Pillow and NumPy). The icon and all sounds are original and were generated by these scripts.

CI (`.github/workflows/ci.yml`) runs the package tests on Linux and builds and tests the app on a macOS runner.

## Configuration

All build-specific values live in `Config/*.xcconfig` and reach the app through `Info.plist`, where `AppConfiguration.swift` reads them:

| Setting | Where | Default |
|---|---|---|
| Bundle ID | `LUMA_BUNDLE_ID` | `com.example.lumagrid` (placeholder) |
| Display name | `LUMA_DISPLAY_NAME` | `LumaGrid` |
| StoreKit product prefix | `LUMA_PRODUCT_ID_PREFIX` | `com.example.lumagrid` |
| Privacy policy / support URLs | `LUMA_PRIVACY_POLICY_URL`, `LUMA_SUPPORT_URL` | empty, so the links are hidden |
| Ads on/off | `LUMA_ADS_ENABLED` | Debug `YES` (Google test IDs), Release `NO` |
| AdMob app / unit IDs | `LUMA_GAD_APP_ID`, `LUMA_GAD_INTERSTITIAL_ID`, `LUMA_GAD_REWARDED_ID` | Debug: Google's official sample IDs. Release: empty |

Put real values in **`Config/Secrets.xcconfig`** (git-ignored; copy `Config/Secrets.example.xcconfig`). Never commit real credentials. In xcconfig files, write URLs as `https:/$()/host/path`, because `//` starts a comment.

Gameplay, economy, and ad-frequency tuning lives in `GameConfiguration`, `EconomyConfiguration`, and `InterstitialPolicy` (LumaGridCore), referenced from `AppConfiguration`.

Safety rails:
- `AdsConfiguration.status` disables ads if IDs are missing or malformed, if a Debug build uses non-test IDs, or if a Release build contains Google's sample IDs.
- The **Validate Release Configuration** build phase (`Scripts/validate_release_config.sh`) fails a Release build that contains sample ad IDs, and fails an *archive* that has no AdMob app ID.

## Ads (Google Mobile Ads 13.x + UMP 3.x)

- Formats: **interstitial** (only when leaving a finished round's results screen) and **rewarded** (only after the player taps the offer and confirms "Watch an ad to earn 50 coins"). No banners, no app-open ads, and no ads on launch, during play, while paused, or during animations.
- Interstitial caps (`InterstitialPolicy.standard`): none during the first 2 completed games, then at most one every 3 completed games, at least 180 s apart, and at most 3 per rolling hour. Counters are persisted, so restarting the app does not reset them. **Remove Forced Ads** suppresses interstitials entirely; rewarded ads remain available, as the shop states.
- Rewarded coins are granted only from the SDK's earned-reward callback, at most once per presentation (`RewardGrantGuard`). The amount is LumaGrid's fixed, pre-announced 50 coins.
- If an ad isn't loaded, the player just continues. There are no retries in their path.
- **Consent:** `ConsentCoordinator` requests UMP consent info on every launch and shows Google's consent form when required. The SDK starts and ads load only when `canRequestAds` is true. If UMP reports that privacy options are required, a **Settings → Ad Privacy Choices** entry appears. Debug builds can simulate the EEA with the launch argument `-ump-debug-eea`.
- **ATT:** LumaGrid does **not** request App Tracking Transparency and has no `NSUserTrackingUsageDescription`, so the SDK cannot read the IDFA. Ads still serve, but without IDFA-based personalization. If you later decide to request ATT, add the plist string and a pre-prompt explanation, and update App Privacy answers. Never gate gameplay or rewards on it.

To go live: create the app and two ad units (Interstitial, Rewarded) in AdMob, put the IDs in `Secrets.xcconfig` for Release, set up the GDPR/US-state privacy messages in AdMob's **Privacy & messaging** section, and keep the `SKAdNetworkItems` list in `Info.plist` current. It was copied from Google's official sample on 2026-10-14 (50 entries).

## In-app purchases (StoreKit 2)

| Product ID (with default prefix) | Type | Grants |
|---|---|---|
| `com.example.lumagrid.removeforcedads` | Non-consumable | No interstitials (rewarded ads stay optional) |
| `com.example.lumagrid.theme.nebula` | Non-consumable | Nebula theme |
| `com.example.lumagrid.theme.sunrise` | Non-consumable | Sunrise theme |
| `com.example.lumagrid.coins.small` | Consumable | 500 coins |
| `com.example.lumagrid.coins.large` | Consumable | 1,500 coins |

- Names, descriptions, and prices shown in the shop come from StoreKit. Prices in `LumaGrid.storekit` are local test values only.
- Purchases go through SwiftUI's `PurchaseAction`. Only **verified** transactions grant anything (`PurchaseProcessor`). Transactions are finished after the grant has been saved to disk. Unverified ones are never granted or finished.
- `Transaction.updates` (Ask to Buy approvals, refunds, other devices) and `Transaction.unfinished` are processed at launch. Non-consumable entitlements are rebuilt from `Transaction.currentEntitlements` at launch and on **Restore Purchases**. A refunded theme pack falls back to the default theme.
- Consumable coins are protected against double-crediting by a durable local ledger of processed transaction IDs.
- **Limitation:** there's no backend or account, so coin balances (earned or bought) live on the device and **do not transfer** to a new device or reinstall. The shop says so. Non-consumables do restore.
- If you change `LUMA_PRODUCT_ID_PREFIX`, update the product IDs in `LumaGrid.storekit` too.

## Privacy

- No accounts, no analytics, no backend. Progress is a local JSON file in Application Support (`progress.json`), written atomically. Corrupt files are moved aside to `progress.corrupt.json` and replaced with defaults. Saves are versioned (`schemaVersion`) and migrate step by step.
- `PrivacyInfo.xcprivacy` declares that LumaGrid's own code does no tracking, collects no data, and uses no required-reason APIs (UserDefaults isn't used). Google's SDKs ship their own manifests. Generate Xcode's privacy report from an archive before filling in **App Privacy** in App Store Connect.

## Accessibility

VoiceOver labels on the score, every board cell, tray pieces (size, Prism, "doesn't fit"), the Lumen meter, Pulse, and all store controls. Tap-to-place is an alternative to dragging (tap a piece, then tap the cell for its top-left corner). Placements, clears, and game over are announced. Prisms carry a symbol, not just a color. Respects system Reduce Motion and has its own "Reduce Animations" switch. Sound and haptics are separate toggles. Touch targets are at least 44 pt. The app is portrait-only and iPhone-only (`TARGETED_DEVICE_FAMILY = 1`).
